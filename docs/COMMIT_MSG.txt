Send tool calls CARE cannot score to Jev as WARNs (D21)

Until now every non-Bash tool call (Write, Edit, Read, WebFetch, mcp__...)
was logged raw and never decided (D3), and a Bash call without a command
was an error record. D21 treats any call CARE cannot score as a WARN: it
goes to the Jev adjudicator, and Jev's tier decides allow / ask / deny
exactly as for a Bash WARN. The D14 tier map, D15 failure -> ask and D13
decide_all all apply. Enforce mode emits the same deny/ask JSON (allow
only with decide_all), and dry-run calls Jev for real, logs, and emits
nothing (D17).

"Cannot score" means every tool whose name is not `Bash`, plus a `Bash`
call whose tool_input.command is missing, not a string, or empty or
whitespace.

Proposed action: the POC's non-shell `Name(json)` form. The state carries
`tool: <tool_name>` verbatim and `args: <json.dumps(input, sort_keys=True,
ensure_ascii=False)>`, clipped at jev.context.field_chars, with decodes
from the unclipped args. This is the same text as the call's prior-action
rendering (`call_text_with`), split into its two halves. The state builder
now takes a `jev::Action` (Shell | Tool). The Shell path is the unchanged
`state_from_shell_command_with`, so Bash states and state_hashes are
byte-identical, and the fidelity, smoke and parity tests pass untouched.
The prior-actions context and transcript handling (D16) are unchanged, and
the current tool_use is excluded from the priors as for Bash.
`resolution::JudgeInput` now carries the action and an optional CARE
prompt, which an unscored call has none of.

`[jev] skip_tools` (default []) lists tool names, matched exactly, that
keep the old pass-through: logged raw, no judge, no decision. It must be
an array of non-empty strings. It is sorted and deduplicated, then
fingerprinted, and an invalid value falls back to [] with an error record.
Listing "Bash" warns, because it only exempts Bash calls with no command.
Adding the key changes the default config_fingerprint from
e1b0fc1e6d5d91ad to 2654a8f1b09ee5cc (tests/golden/tunables_default.json
regenerated). It is in `config`, `config --init` and the README table.

Log records for unscored calls keep `tool_input` (truncated + sha256) and
add `care: {"supported": false, "reason": "non-shell tool" | "missing
command" | "empty command" | "command is not a string"}`, `unscored: true`,
`provisional: "WARN"` (a plain string: there is no per-mode score),
`would_adjudicate`, `judge` (same schema as for Bash), `final`,
`would_emit` and `fixes_applied`. A judge failure also writes the usual
`stage: "judge"` error record, which here names the tool and carries
`unscored: true`. Bash records are unchanged.

Cost and egress: every non-skipped non-Bash call is now one Jev round
trip (POC p50 ~226 ms, capped by budget_ms) and one metered request. Its
full input, including Write/Edit file bodies up to the clip and Read
paths, is sent to api.typesafe.ai. The README covers this in "What it
does", "Register as a hook", "Data egress", the mapping, the log schema,
the enforce table and "Known limitations".

Tests: tests/jev_e2e.rs drives the real binary against the replayed POC
fixtures. Write, Read, WebFetch and mcp__server__tool each produce a judge
record whose logged and sent state is the `Name(json)` form, with the
current call excluded from the priors. In enforce mode, T2 gives deny, T5
gives ask, T6 is silent, and T6 with decide_all gives allow. A Bash call
with a missing, empty, whitespace or non-string command goes to Jev, not
to an error record. skip_tools = ["Read"] passes Read through with no
request, while Write is still judged. No key or an unreachable server
gives ask plus an error record, silent in dry-run. Unit tests cover the
tool-call state and skip_tools validation and fingerprinting. Changed
expectations: e2e `bash_without_command_fails_open` becomes
`bash_without_command_goes_to_jev`, and `non_bash_tools_are_logged_raw`
also asserts the judge record.

Unchanged: FIX-001, FIX-002, FIX-003, FIX-004, FIX-005, FIX-006, FIX-007,
FIX-008 (also bounds the unscored judge call), FIX-009, FIX-010, FIX-011,
FIX-012, FIX-013, EXT-001, EXT-002, EXT-003, EXT-004, EXT-005, EXT-006,
and the Jev deviations JEV-DEV-001, JEV-DEV-002, JEV-DEV-003 and
JEV-DEV-004 (JEV-DEV-004's "every unresolved WARN is a fresh call" now
includes unscored calls).
