Expose CARE and Jev tunables in config.toml (D18-D20)

Every numeric knob of CARE and of the Jev adjudicator can now be set in
config.toml. Lexicons, path catalogs and regexes stay embedded. The
defaults reproduce the previous constants exactly, so an empty or absent
config changes nothing.

[care] (D18): L5 weights; tau_low/tau_high for each mode; theta_rule,
theta_sem and the H_sem class set; provenance pi per tier; the 10 L2 class
base scores; the 5 L1 ladder values; the 8 L3 tier scores. Per-rule
overrides by SE-P id: `enabled = false` removes a rule from L4 matching and
from p_rule, and `confidence` feeds both L4 (pi*conf) and p_rule.

[jev] (D19): the tier thresholds (a5 transport, a1/a7 sensitive, a6
unknown and its f5 gate, f5 deny/ask, d1 obfuscated, b4 irreversible),
the first-match tier order, the T1..T6 -> allow|ask|deny map, and the
context limits (4,000-char clip, 12,000-char history budget, max level
L0/L1/L2). `rubric_file` loads an alternative rubric YAML with the same
parser and lint as the embedded one. Its rubric_hash is logged and is the
hash in the judge record. An unreadable or invalid file falls back to the
embedded rubric with an error record. A tier that reads an axis the rubric
lacks can never fire, and each one produces a warning record.

Guardrails (D20): values are validated one at a time. Weights must be
finite and >= 0, probabilities and thresholds in [0,1], tau_low < tau_high,
and class names, tier names and SE-P ids must be known. An invalid value
falls back to its own default with an error record naming the key, and
unknown keys produce warnings. The hook still fails open. Every log record
now carries `config_fingerprint`, a 16-hex sha256 of the canonical JSON of
the effective tunables (independent of key order and spelling), plus
`overrides[]` (the dotted keys that differ from the default) and
`rubric_hash`. `cancelli config` lists every tunable with its value and
source, and the effective enabled/confidence of all 139 rules.
`cancelli config --init` appends every tunable at its default, each with a
one-line explanation and its provenance (paper eq., repo file or FINDINGS
section), all commented out.

The values are threaded through the engine and Jev as a `Tunables` struct
(src/tunables.rs; `Options.care`, `jev::Settings.tuning`), not globals.
Tier predicate text in the judge record (`tier_rule`) shows the thresholds
in force.

Tests: the parity suite, the Jev fidelity/offline tests, the smoke replays
and every pre-existing e2e test pass unchanged on defaults. A golden
snapshot (tests/golden/tunables_default.json, fingerprint e1b0fc1e6d5d91ad)
pins Tunables::default(). tests/tuning_e2e.rs drives the real binary with a
temp HOME and XDG_CONFIG_HOME and shows that each group changes the
outcome:
- lowering balanced tau_high turns the rsync WARN into DENY;
- disabling SE-P-103 drops it from fired_rules and gives ALLOW;
- raising gtfobins pi makes p_rule fire on a GTFOBins shell;
- mapping T5 to deny changes the enforce output from ask to deny on the
  replayed POC fixture;
- a smaller history budget, a field clip and max_level change the rendered
  state;
- a rubric_file with a renamed axis warns, and T2/T5 never fire.
It also checks that invalid values fall back per key with an error record,
exit 0 and silent dry-run. The fingerprint is stable across layouts, and
overrides[] lists exactly the changed keys. `config --init` pins nothing,
and uncommenting it reproduces the defaults. The README table is checked
against the code.

Docs: README "Tuning" (all tunables with default, meaning and provenance;
examples; calibrating from logs by fingerprint and overrides; a caution
that the Jev thresholds were calibrated on the embedded rubric and on the
ProCreations corpus) and a constant inventory listing what stays embedded
and why.

Unchanged: FIX-001, FIX-002, FIX-003, FIX-004, FIX-005, FIX-006, FIX-007,
FIX-008, FIX-009, FIX-010, FIX-011, FIX-012, FIX-013, EXT-001, EXT-002,
EXT-003, EXT-004, EXT-005, EXT-006, and the Jev deviations JEV-DEV-001,
JEV-DEV-002, JEV-DEV-003, JEV-DEV-004 (the budget JEV-DEV-002 describes is
now `jev.context.history_chars`).
