Adjudicate CARE WARNs with Jev (jev-1.13.0) instead of the stub

Replaces the stubbed WARN judge with Jev, TypeSafe AI's hosted rubric model,
as ported from the jev_gate POC (decisions D11-D17). Only Bash commands CARE
leaves at WARN with no skip predicate reach Jev; CARE's static ALLOW and DENY
are unchanged (D12).

Context (D16): the proposed action (`tool: bash`, args = the command), the
user request from genuine human prompts in the session transcript (a
documented, unit-tested filter drops tool results, isMeta/compact-summary/
sidechain records, system reminders, task notifications, local-command
output and inter-session messages), and prior tool_use calls with args
verbatim. Tool results and agent prose are never read. The level degrades
from L2 to L1/L0 when the transcript is missing or does not yet contain the
current tool_use, and the achieved level is logged. The state uses the POC
render template byte-for-byte: same headers, 4,000-char clipping,
12,000-char history budget, decoded-forms section, results never rendered.

Rubric: data/jev/v1_policy_distilled.yaml vendored verbatim via
include_str!. All 40 axes are parsed, and per-level question selection
applies `requires` (L0/L1 38, L2 39). A test recomputes rubric_hash with the
POC's exact algorithm (Python json.dumps separators, sort_keys,
ensure_ascii=False) and asserts 0fd1f245ae1c7ef3.

Decision (D14): the POC's signals() with the rubric's declarations, then the
6-tier first-match rules of the spec, thresholds unchanged. "unknown" is the
declared a6 argmax predicate, gated on f5 > 0.8. T1/T2 -> deny, T3-T5 -> ask,
T6 -> allow. A Jev allow emits nothing unless --decide-all / decide_all =
true (D13). Every failure -> ask plus an error record (D15): no key, key file
with group/other permissions, transport error, timeout, non-2xx,
unparseable body, missing answers, or response.model != jev-1.13.0.

Transport: blocking ureq 3 + rustls, POST {base_url}/v1/systemone with a
Bearer key (env var named by api_key_env, else a 0600 api_key_file; never
logged, redacted from errors). 3,000 ms per request, 5,000 ms budget, one
retry on 408/429/5xx/timeout honouring retry-after(-ms) within the budget.
Captures x-typesafe-request-id and usage. Dry-run calls Jev for real and
logs the full judge record (D17); `cancelli judge "<cmd>" [--transcript]
[--request]` prints the same record; `cancelli config` shows the new keys,
their sources, and where the key was found.

Also fixes Env::from_process() to skip non-UTF-8 environment variables, so
one of them can no longer panic the hook before its panic guard.

Tests: the 8 POC smoke-gate states render and hash byte-identically to the
POC. The POC's real cached responses for them (8 files, screened for
credentials) replay to the POC's own signals, tiers T6/T2/T6/T2/T6/T2/T6/T5,
and all 10 smoke checks. The real binary is exercised against a local
stand-in server for connection refused, hang/timeout, missing key, loose key
file, wrong model, 503-then-ok and 401 (each: ask, error record, exit 0 in
dry-run), and for decide_all on/off in enforce mode. The exact request on
the wire is asserted, and so is the absence of any key, result, prose or
system-reminder leak. tests/jev_live.rs (ignored) runs the smoke gate and
one WARN through an installed binary against the real API:
TYPESAFE_API_KEY=... cargo test --test jev_live -- --ignored

Behaviour change: an unresolved WARN is now `final = "ask"` when Jev fails
(including with no key) instead of `unadjudicated`; the e2e expectation is
updated accordingly. backend = "stub" restores the old behaviour.

Deviations from the POC (README "Deviations from the POC"):

JEV-DEV-001 user_request keeps the most recent prompt (POC keeps the oldest 4,000 chars).
JEV-DEV-002 tool results are never read, so the history budget counts call text only.
JEV-DEV-003 3 s / 5 s budget / one retry, failures ask (POC: SDK 60 s, 2 retries, 30 s).
JEV-DEV-004 no answer cache.

CARE divergences carried forward: FIX-004 (first-token parsing) and FIX-008
(judge timeout) now apply to text judges; Jev's backstop timeout asks.
Unchanged: FIX-001, FIX-002, FIX-003, FIX-005, FIX-006, FIX-007, FIX-009,
FIX-010, FIX-011, FIX-012, FIX-013, EXT-001, EXT-002, EXT-003, EXT-004,
EXT-005, EXT-006.
