Judge Jev through OpenRouter's Decisions API (D28)

A new `[judge] provider` key selects who serves the judge: "typesafe"
(the default; every value exactly as before) or "openrouter"
(OpenRouter's Decisions API, POST https://openrouter.ai/api/alpha/decisions,
which hosts the same Jev as typesafe/jev-1.13 and reports it under a
dated snapshot slug such as typesafe/jev-1.13-20260917). The wire format
is the same, so the state, the questions, the tiers and the thresholds
are untouched and no calibration file is involved.

A provider only supplies the defaults of base_url, path (new), model,
expected_model and api_key_env, plus the name of the base-URL override
variable (TYPESAFE_BASE_URL / OPENROUTER_BASE_URL). Any of those keys set
in the file still wins. The provider is read from the file only: an
exported OPENROUTER_API_KEY by itself changes nothing, so an existing
TypeSafe or local-backend setup cannot change because of the
environment. `cancelli config` prints judge.provider and judge.path with
their source.

judge.expected_model gains one wildcard: a single trailing `*` after a
non-empty prefix makes it a prefix match (a bare `*` is refused, since
it would void the D15 model check). OpenRouter's default is
typesafe/jev-1.13-*, so a re-dated snapshot keeps working while another
listing (typesafe/jev-1.14-...) is still a D15 ask with an error record.
TypeSafe's default stays the exact pin jev-1.13.0, and a calibration
file is pinned by the same rule.

"Is this Jev?" has one answer, provider::is_jev, for a reported model or
an expected_model under either provider. `cancelli calibrate` refuses
either name as an online target and accepts references judged through
either provider; the "calibrated on jev-1.13.0" warning and the rubric
model warning use it; `cancelli eval` reuses logged answers across the
two providers instead of re-querying.

overrides[] (every log record, `cancelli config`, eval reports) is
computed against the provider's defaults, so the OpenRouter
expected_model is not reported as an override the user never made. The
fingerprint still includes expected_model (D23) and so differs by
provider, but only when the file says so.

Code:
- src/jev/provider.rs: Provider, ProviderDefaults, TYPESAFE /
  OPENROUTER, is_jev.
- config: judge.provider and judge.path (must start with '/'); the file
  is read once (read_file); Env.base_url is gone (the override variable
  is the provider's, read from the captured environment).
- client: Transport.path and Transport::url (strict: the path is
  validated by config); jev::model_matches.
- tunables: load() takes the provider's expected_model default;
  Tunables::defaults_for and overrides_from; tunables::Loaded.overrides.
- Judge records and judge error records carry backend_path.

Tests:
- New tests/openrouter_e2e.rs (5, real binary + replay server, which now
  answers on any path and records the request line): provider in the
  file (path, Bearer key and model slug on the wire), an exported key
  alone changing nothing (no request leaves), a re-dated snapshot
  accepted and another listing refused, a local backend ignoring the
  key, and the `cancelli config` output with overrides = [].
- eval_e2e: logged Jev answers are reused under the other provider.
- config: three D28 tests; provider (is_jev), Transport::url,
  model_matches and the expected_model wildcard validation.
- Every e2e harness also clears OPENROUTER_API_KEY / OPENROUTER_BASE_URL.
- Live (#[ignore]): the two jev_live bodies move to tests/common/live.rs,
  parameterised by Provider; tests/openrouter_live.rs runs them through
  OpenRouter (OPENROUTER_API_KEY / OPENROUTER_BASE_URL, the decisions
  path, a typesafe/jev-1.13-* snapshot asserted as response.model). The
  installed-binary test writes `provider = "<name>"` into config.toml.
  Run live: both pass. OpenRouter reports usage in TypeSafe's shape
  (asserted) and sends no x-typesafe-request-id (request_id is null,
  printed).

188 offline tests pass. clippy --all-targets and fmt are clean. The
